## Actual adapter and preserved product paths

- `POST /v1/provider-actions/generate-image`, `edit-image`, and `model-matrix` use the configured server-side image provider. The default remains the Workers AI binding with `@cf/black-forest-labs/flux-2-klein-4b`; `AI_IMAGE_PROVIDER=openai` opts into the OpenAI Images API adapter with `OPENAI_IMAGE_API_KEY` (or `OPENAI_API_KEY`) and server-side model configuration. The old arbitrary `AI_PROVIDER_URL`/token proxy is removed. Other provider actions return an explicit not-implemented response; there is no mock image, text-only substitute, alternate-model retry, browser credential, or Supabase fallback in this path.
- The browser may label a request as `generationProvider`, but the server accepts it only when it matches the configured provider. OpenAI requests use `/images/generations` for new images and `/images/edits` for references, persist the provider/backend/model in request, job, R2 and Gallery metadata, and retain the provider request ID in the receipt. A missing key or unsupported model fails before durable admission.
- `GET /v1/image-ai/requests/:requestId` reads the same private request without inference. A readable HTTP 200 receipt may still have `success:false` and `state:unknown/failed/running`. Only complete, structurally valid, persisted candidate sets return success.
- The existing `generation_jobs`, `generated_images`, media signing gateway, Gallery/History/Jobs listings, revisioned Canvas documents, and workspace-artifact save pipeline are reused. Generated IDs/paths are deterministic `ai-<UUID>-<index>` / `generated-images/ai-<UUID>-<index>`; no old test data is imported.
- `GeneratePage` selects and labels the actual Cloudflare candidate. Dedicated fitting is not routed through the old generic hosted text-generation branch. Fitting keeps body/age/gender and source identities in durable metadata. Missing image-content verification is labeled unverified, never reconstructed as a positive verdict from saved prompt text.
- `UsageStats` now uses the D1 ledger, not the old Supabase RPC or a fabricated 25-image remainder. Six metrics distinguish remaining/completed/running/uncertain/monthly limit. A failed request to the usage service displays unavailable, not zero. Stale user/brand results are ignored. Admin counts/estimated cost/inference latency are image-AI-scoped; invoice, account-wide usage, Edge/CPU and unrelated feature measurements remain null.

## Input and output contract

- Verified current session plus editor role for new requests; viewer role plus exact request creator for receipts. Check access again before/after inference, after R2, and before delivery. Viewers cannot repair unfinished saves. Caller-supplied ownership/admin claims have no authority.
- Explicit rights confirmation and the existing legal-safety checks remain. The shared legal-safety file is pure code currently located under the old functions tree, not an SDK or network dependency; move that source location when retiring the old tree in stage 10.
- Browser preprocessing sends PNG copies with long edge at most 512 px, retains original input images, and records original/sent dimensions. Maximum four ordered references; no silent truncation. A person reference without a garment is rejected before fetch rather than shifted into garment slot 0. The server never fetches arbitrary reference URLs.
- Server accepts bounded PNG/JPEG bytes, checks structure and dimensions, and requires output dimensions to match. Output size is 256–1920 per axis, multiples of eight; 4:5 uses 1024×1280. This is not a full server-side pixel decoder or semantic-quality validator.
- Generate/edit accept 1–4 candidates. Fitting preserves all selected supported combinations, up to the existing three-pattern limit: adult 20s–50s, slim/regular/plus, male/female, optional existing skin-tone/hair-length choices. Image-only garment input uses a reference-preservation instruction, not a fabricated description.
- Metadata retains source IDs/paths and lineage but redacts raw image/URL strings and credential-like keys. Raw reference images and bearer tokens are not written to the request/job metadata.
- Masked Canvas/print/fabric edits now reuse `providerMask.ts` and the workspace-artifact writer with explicit `reference-guide-protected-composite-v1`. The model receives the source, at most two additional ordered references, and a final white-editable/black-protected visual guide (four references total). Extra references are rejected, not dropped. This is **not native inpainting**: raw mask fields and unsupported quality settings are still rejected by the model adapter.
- The browser composites the real provider result into the original PNG frame (up to 4096 px per axis and a 10 MiB canonical source PNG). Fully protected pixels retain the decoded source RGBA, including transparency; feathered edges use premultiplied-alpha blending. Full source/mask SHA-256 and the guide index bind postprocessing to the submitted source. Creating new transparent output remains unsupported; preserving source transparency is a distinct operation.
- Four-candidate Canvas edits are four actual model calls, not one inference. Raw `ai-<UUID>-<index>` artifacts are hidden from Gallery and the original Jobs row stays processing until all deterministic `wa-<UUID>` final saves are read back. Final images keep actual workspace job IDs, a common AI batch ID and raw-provider parent/provenance. Compositing does not consume another model unit.
- Print/fabric final save/history acknowledgement is connected, but precise design placement and large multi-design sets are **not feature-parity accepted**: placement/layer metadata alone does not make FLUX obey exact placement, and more than two additional references cannot fit beside source and guide. Reuse the existing composition/placement renderer for this remaining work; do not truncate input or call metadata preservation visual fidelity.

## Durable admission and recovery

1. Validate identity, rights, input, parent ownership, model, feature flag and media secret. Atomically reserve a request, job and every candidate with immutable fingerprint/execution ID. Concurrent copies of the same UUID admit one execution; a changed request conflicts.
2. Mark each candidate running immediately before its single upstream call. Process candidates sequentially. Each call uses the bounded `AI_IMAGE_TIMEOUT_MS` observation timeout (45 seconds by default, at most 90 seconds); a timeout/exception is unknown, not proof that the provider did nothing. Later candidates are not submitted after an uncertain result.
3. Record output digest, size, dimensions and cost estimate before the conditional R2 create. Read the exact object after a lost PUT response. Commit image/job links only for the exact owner, brand, path and job. Never adopt another row just because it has the same ID.
4. A receipt read/restart can finish an already stored matching object without another model call. Missing bytes, foreign metadata or unrelated rows remain unresolved; no fabricated success, overwrite or compensating deletion. Lost D1 batch responses are read back before deciding their outcome.
5. LocalStorage stores only scoped hashed-input/request IDs. Before a protected request can reach the provider, the existing Canvas IndexedDB asset store commits and reads back a bounded (42 MiB) source PNG/mask/prepared-reference/settings snapshot. Origin/user/brand/request scope, source/mask hashes and the canonical input fingerprint are checked on recovery. Descriptive signed URLs and credential-like metadata are removed, but actual submitted image bytes remain part of identity. This cache is **not encrypted**, not cross-device storage and not proof against OS eviction or a browser-storage wipe.
6. One in-flight identical invocation is coalesced before asynchronous hashing. Unknowns survive reload; refreshed signed URLs in descriptive metadata do not change identity. After a lost response, only GET of that ID occurs. An explicit resume may POST the **same** ID only after a definite request-not-found response. Generic 401/403 does not discard the ID because permission may have changed after inference. Unknown inference without stored output never triggers another model call.
7. Protected requests retain the completed receipt and input snapshot through decode/composite/final-save failures. Each final save has a deterministic child UUID, is read before writing, and is read again after a lost response. `GET /v1/workspace-artifacts/:requestId` can repair an exact owned pending save from immutable R2 bytes without inference or another PUT; viewer reads cannot perform repairs. Server checks actual source candidate, creator, brand, frame, SHA/size and current editor role, then reconciles the original batch only after every final exists.
8. Canvas and Gallery expose scoped pending-work recovery. Canvas checks the original source hash/project/parent and skips exact candidates already placed; rollback touches only newly placed objects. Canvas acknowledges only after manual document save plus server readback. Print/fabric acknowledges after its existing durable artifact/history handoff; Gallery does not consume a Canvas-bound pending acknowledgement. Only the exact acknowledged snapshot/key is removed; unrelated local Canvas assets remain. Definitively failed input/receipts can clear their exact pending entry. Cross-tab locks serialize resume/acknowledgement, not all independent completed clicks.

Existing signed media capabilities last at most one hour; this work does not claim immediate invalidation of every already issued capability on ordinary logout. Source/mask reload and native browser PNG decode/compositing are tested below. OS process termination/storage failure, cross-device unfinished-input recovery and production auth remain separate QA. Canvas now persists the exact scoped destination UUID and immutable pending body before POST, adopts that route before dispatch, and performs GET-only inspection after full reload. The latest working edits remain separate from the uncertain write; same-ID create reconciliation and revision-CAS updates never silently overwrite foreign or changed content. Source-project aliases preserve the existing image receipt across that local-to-remote transition without changing source/parent/ownership checks. Full contract, limits and evidence: [CANVAS_SAVE_RECOVERY.md](CANVAS_SAVE_RECOVERY.md).

## Limits and measurement

The default **application** policy is 25 image units per brand/UTC month, 100 admitted candidate units per Heavy Worker/UTC day, 5,000 estimated Neurons per Heavy Worker/UTC day, two concurrent requests globally, and one running request per user. Admission reserves the estimated output-size/reference cost in integer hundredths of a Neuron. The anonymous daily counter is not replenished by request/user/brand deletion or uncertain/partial provider outcomes. Monthly units release only candidates classified definitively failed; unknown/storing results remain held.

For this model the estimator uses 59 microUSD / 5.37 Neurons per input 512×512 tile and 287 microUSD / 26.05 Neurons per output tile. Each dimension is rounded up independently to tile boundaries. These are estimates based on the [Cloudflare model page](https://developers.cloudflare.com/workers-ai/models/flux-2-klein-4b/) and [pricing table](https://developers.cloudflare.com/workers-ai/platform/pricing/), checked 2026-09-06. Pricing/Neuron conversion may change; revalidate before changing the admission policy.

Cloudflare currently describes a 10,000-Neuron daily free allocation and requires a paid plan for excess use. Heavy's internal 5,000 estimate limit is **not** a reservation of that allocation: MyPro, probes and other services share the account. Actual invoice/remaining allocation/CPU/p95/p99/load are not measured here. The account-subscription read returned 403 for absent billing-read authority; no paid plan, new key, billing permission or premium model was purchased/enabled. Do not infer a fresh billing-plan readback from `wrangler whoami` or an inference HTTP 200.
