# Canvas stable-save and reload recovery

Updated: 2026-09-06 18:06 JST. This is a staged implementation/verification checkpoint, not authenticated production or full migration completion.

## Existing storage and API contract

This reuses `canvas_documents`, its primary key/revision, the existing POST/GET/PATCH routes, Canvas serialization, localStorage and the existing IndexedDB image store. No migration, new database/bucket, test-data copy or account creation is needed.

- First Save selects the destination UUID before any POST. Existing local projects derive a stable UUID from API origin/user/brand/local-project ID; unrelated blank documents receive independent random IDs. The same scoped draft and destination are written and read back before the page adopts that UUID route.
- POST supplies `id`. The SQL is `INSERT ... SELECT ... WHERE editor-predicate ON CONFLICT(id) DO NOTHING`. Exact owner/brand/title/snapshot retry returns the existing row, never an overwrite. JSON key ordering is immaterial, array ordering is not. Different content, owner or brand conflicts. An interrupted INSERT is reconciled by reading that exact row; a failed/missing read is unavailable rather than a fabricated success/conflict.
- Both INSERT and revision-CAS PATCH include the current brand owner/joined-editor predicate inside SQL, in addition to HTTP checks. A role removal immediately before execution prevents the write. Shared editors may update a permitted document without changing its owner. PATCH response loss is resolved by GET; repeating its old revision cannot increment twice.
- The browser captures the current bearer/user and checks caller user/brand/route boundaries before and after requests. Canvas calls bypass the legacy automatic auth-refresh retry wrapper. POST/PATCH do not auto-replay on 401/403/409/503/network failure. Requests have a 20-second transport timeout.

## Local recovery semantics

`canvasDocumentSaveRecovery.ts` keeps a versioned, exact API-origin/user/brand/document key. Its entry contains the latest working title/snapshot, verified owner/revision, and a separate immutable pending write body/expected revision/write ID. Auth headers/tokens are not stored. The cache cap is **2 × 1024 × 1024 serialized characters**, not a byte or encryption guarantee. Existing API payload limits still apply.

1. Save copies the click-time body; cache commit/readback precedes dispatch. In-process and Web Locks serialize the same document. Editing remains possible while the request is outstanding.
2. A response failure triggers only exact-ID GET. Matching content and the expected next revision settle the pending write while preserving newer working edits. Unknown/mismatching/foreign results remain unconfirmed. Known existing documents that disappear are not recreated.
3. Full page load performs GET inspection only, never POST/PATCH. The current scoped draft survives failed reconciliation; a global legacy working set is not adopted as another user's remote document. Inspection re-reads the local cache after GET so edits made during that GET are not overwritten.
4. A later explicit Save may retry the identical uncertain body after a missing create destination or an unchanged update revision. It may then save the click-time newer edits with the just-confirmed revision. This does not authorize re-inference or another document ID.
5. Exact `400 invalid_canvas_document` plus a missing-create/unchanged-update readback permits discarding only that rejected pending request, retaining its ID/latest draft. Corrected input can be saved on a later explicit action; unknown outcomes and permission failures do not take this shortcut.
6. Debounced working-draft updates plus `pagehide`/hidden-visibility flush preserve ordinary page reload edits. Quota/corruption failures are visible. Only explicit “reload latest” discards the dirty version after a context-bound server readback.

Old local bookmarks resolve through the same scoped deterministic ID before loading a lightweight local index. Source-project aliases preserve an existing image recovery request across the known local-to-remote ID transition; aliases do not grant backend authority or bypass original source/parent checks. Image request acknowledgement still requires a verified Canvas save and no newer unsaved working edits.

Limits: localStorage/IndexedDB are not encrypted or cross-device recovery, and OS termination/storage eviction is not proven. Web Locks serialize saves but do not provide independent per-tab draft isolation or real-time collaboration. Broader browser/device/authenticated production QA remains open. The final old-bookmark lookup and definite-invalid-input correction have targeted source/runtime tests; they were added after the 11-check browser run below, not separately browser-proven.
